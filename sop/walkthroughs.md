# SOP 纸面场景验收

版本：1.0.0。以下为虚构场景的流程一致性检查，不代表代码、线上功能或真实交易测试已通过。

## 场景 A：人民币商品商城，在线付款

1. 入驻记录商品价格 CNY、付款支持情况与资料来源，身份从服务端绑定。提供 code 后记为配置输入已提供，另查必要配置和接口结果，不笼统说渠道未开通。
2. 网站交付按品牌选择区块与数量，逐步提供预览，购物车独立设计。Basic 文件配额交服务端权益验证；上传后刷新重读。
3. 支付 SOP 保留建单重试标识，核对渠道金额和币种；订单过期后到账仍登记付款，库存不足交操作员选择履约或退款。
4. 部分退款完成只追加相应退款事件，保留原付款流水；CRM 不把 CNY 金额直接计作 JPY。
5. 对支付页读取、重复请求、晚到账和部分退款提供验证证据。真实交易未做就明确记未验证，按既有发布规则判断网站交付。
6. 已获授权发布时提供版本、健康和回滚证据；文档存在或模块单测通过不能替代这些记录。

核对结果：涉及入驻、网站、支付三个 SOP；维护／故障按需触发。没有新增工作流阶段，也没有把配置存在等同于付款成功。

## 场景 B：到店付款的预约服务

1. 入驻固定真实时区、服务时长、人员、营业时间和取消规则；能力为预约、无在线支付。
2. 网站按服务内容设计，后台配置人员与时段。支付字段不适用按 Workflow 支持的规则留证，不强制接支付。
3. 预约 SOP 要求项目 Adapter 完成原子占位与冲突检查；不能声称仓库已有专用排期 core。
4. 两人同时抢最后一个名额，只允许配置容量内的成功结果；改期失败保留原预约；重复取消不多次释放名额。
5. 验证真实保存、时区边界、权限与并发；未实现 Adapter 时流程不能判定完成。

核对结果：涉及入驻、网站、预约三个 SOP；付款子流程可不适用，预约规则仍必须验证。

## 场景 C：两个会话修改同一项目，其中一个中断

两个任务固定各自基线和范围，草稿可并行。任务一 CAS 提交后，任务二旧 revision 失败，重新读取并合并。若发布响应超时，先查询实际运行版本再决定恢复；不能把“任务中断”解释为“没有发布”。维护记录保留旧验收，故障记录保留部分成功证据。

核对结果：五会话目标不授予五次并行生产写入权限；没有用新报告状态覆盖 Workflow 权威状态。
