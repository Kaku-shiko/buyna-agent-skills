# 06 故障恢复 SOP

ID：incident-and-recovery · 版本：1.0.0 · 负责人：技术执行者；交付负责人负责反馈和交接。

适用：模型／账号额度、任务中断、连接失败、版本冲突、测试失败、发布异常或交易结果不明。输入为故障时间、任务范围、脱敏日志、最后检查点及实际副作用记录。遵守[统一执行规则](execution-contract.md)。

## 执行步骤

| stepId | 动作与角色 | 输出和完成检查 |
| --- | --- | --- |
| contain | 技术执行者限制异常影响，只暂停有关操作 | 明确受影响租户、服务和写入；不默认停止无关业务 |
| inspect | 技术执行者核对任务状态、文件、数据库、订单与运行版本 | 已保存、未保存、已发布和不确定项分开记录 |
| classify | 技术执行者确定原因、可重试性和依赖 | 异常分类、所需输入、恢复负责人；不把所有错误归为额度不足 |
| recover | 技术执行者查询副作用后从验证过的检查点恢复或回滚 | 有上限重试、幂等键／效果查询、CAS；不重复扣款或退款 |
| verify | 验证者检查健康、受影响功能和数据一致性 | 恢复后的实际结果与版本；不能只看进程已启动 |
| handoff | 交付负责人报告结果及后续 | 原因、已完成、未完成、恢复入口和预防措施 |

## 异常处理表

| category | 处理 | 自动重试条件 |
| --- | --- | --- |
| missing_input | 指明缺失事实和用途；继续独立工作 | 等输入，不循环请求 |
| auth | 检查登录／配置引用与授权范围 | 凭据或权限修复后；不打印密钥 |
| quota | 保存检查点，说明额度或资源限制 | 确认额度恢复后按既有执行器策略 |
| connection | 区分临时网络故障与配置错误 | 仅临时错误，有上限退避 |
| version_conflict | 加载最新 revision、合并并重新验证 | 不原样覆盖或循环重发 |
| test_failure | 保存失败证据并修复 | 修复后重跑受影响测试 |
| release_failure | 查询实际发布版本／服务状态，选择修复或回滚 | 副作用明确且已有发布授权 |
| payment_uncertain | 查同一订单／退款及渠道记录 | 先核对结果；不重新创建交易 |
| manual_pause | 保存范围、原因和检查点 | 仅收到继续指令后 |
| unknown | 保留证据、进一步诊断 | 原因未知时不盲目重放副作用 |

重试上限沿用当前执行器配置并记入记录；无安全重试策略时交接人工，不凭 SOP 任意增加次数。进程重启、租约到期或用户再次说“继续”，都不能作为副作用未发生的证明。

## Skill 与模块

恢复原业务时重新调用其 Skill；发布异常用[发布 Skill](../skills/buyna-aws-release/SKILL.md)，交易异常用[状态同步](../skills/buyai-globepay-status-sync/SKILL.md)，验证用[测试 Skill](../skills/buyna-testing-quality/SKILL.md)。依赖[Workflow](../packages/buyna-workflow-state-core/package.json)、[交付状态](../packages/buyna-delivery-state-core/package.json)、[运行槽位](../packages/buyna-runtime-slot-core/package.json)与实际项目运行存储。

## 完成与反馈

报告如：“代码已保存；连接中断；尚未发布；连接恢复后从后台接入继续。”如果已部分发布必须明确说明，不能声称“没有修改或发布”。保留回滚前后版本和检查证据，数据迁移按实际补偿方案处理。

恢复完成须有可复核结果；仍被外部条件阻塞时记录负责人、等待条件和恢复入口。向客户／第三方发送事故通知必须获得明确授权。复盘只将不含客户私有数据的通用结论写回规范。
