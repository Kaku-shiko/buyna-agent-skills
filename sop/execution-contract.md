# 统一执行规则与模板

版本：1.0.0。适用于[全部 SOP](index.md)。本页的报告字段是交换格式，不是新的 Workflow 状态机。

## 每一步必须明确什么

| 字段 | 要求 |
| --- | --- |
| 流程和步骤 | sopId、sopVersion、stepId；步骤 ID 在同一 SOP 内唯一 |
| 范围和版本 | runId、受保护项目引用、输入摘要、代码基线、Skill／模块版本 |
| 输入和前置条件 | 数据来源、能力、已有授权、所需资源；缺项标明是否阻塞 |
| 执行 | 负责人、动作、允许的工具范围、对应 Skill 和模块 |
| 输出与检查 | 实际产物、确定性检查、证据引用、检查时间 |
| 授权 | 使用已有有效授权；新增决策记录范围、版本和来源 |
| 异常和交接 | 原因分类、已发生副作用、重试或补偿办法、下一步及负责人 |

允许的工具范围由步骤和已有授权决定：资料读取和分析、项目内代码修改、受保护配置引用、验证工具、已授权部署工具。工具可调用不代表可以跨租户操作或向他人发消息。真实客户记录只放受保护存储，公开仓库只保留空模板与虚构示例。

## 统一操作规则

- 已授权且范围不变的工作继续执行。缺少业务事实时提出具体问题，同时推进无依赖工作；不重复要求批准每个字段或模块调用。
- 新费用、破坏性操作、越出授权范围或缺少授权的生产操作须取得适用授权；发送邮件或消息给他人须有明确授权。
- 价格、库存、法人、退款承诺及法律披露不得编造；法律文本由真实主体信息与适用规则确认后使用。
- 五个会话是产品目标，不代表当前部署已验证，也不等于五个同时发布。项目隔离读取和草稿可并行；同项目合并、迁移、Workflow CAS 和发布须串行协调。
- 每个并发工作单元固定任务 ID、输入摘要、代码基线和范围；新消息只使相关结果失效。旧 revision 冲突后重新加载、合并和验证，不覆盖最新结果。
- 重试前检查是否已有成功副作用。付款、退款、通知、资源创建及发布不能根据聊天重试直接重放；使用稳定幂等标识和业务查询。
- 展示“当前步骤、可查看结果、待补项、下一步、负责人、更新时间”。错误明确说明已保存什么，不能用“没有修改网站”掩盖已保存或部分发布的事实。
- 公共网站默认使用正常售卖／预约文案；登录入口写“登录”。预览和内部报告如实标注未接入与未验证，不将演示性数据伪装成可销售库存。

## Workflow 映射

沿用 [现有契约](../skills/buyna-website-builder/references/workflow-state-contract.md)，阶段 ID 只有下列七项。文档中的业务步骤可以多于七个；不可用文档步骤顺序代替状态机的转换规则。

| gate ID | 业务阶段 |
| --- | --- |
| customer_intake | 资料与范围 |
| design_and_structure | 设计和页面结构 |
| frontend_code | 前端实现 |
| dashboard_integration | 后台接入 |
| checkout_payment | 结账和支付 |
| testing_upload_gate | 测试与上传检查 |
| aws_release | 发布 |

每次恢复用 `loadVerifiedWorkflow()`；转换通过现有 core API 生成，使用同次加载的 `loadedState` 调用 `saveWorkflow`。签名和 CAS 规则不可绕过。N/A 仅在现有状态机支持且能力证据满足时使用，不能跳过失败检查。维护使用现有 repair slice，不重写历史完成记录。

## 执行记录模板

复制到受保护的项目记录中，填写真实值；不能把模板占位符作为完成证据。

```text
任务／项目引用：
SOP ID／版本／步骤 ID：
代码基线／Skill 与模块版本：
负责人／记录时间：
输入来源与摘要：
前置条件与能力：
授权记录引用与范围：
执行动作与工具范围：
已产生副作用及幂等标识引用：
实际输出／产物引用：
检查项目／结果／证据引用：
当前 Workflow revision／gate（如适用）：
异常原因／恢复或补偿方案：
下一步／负责人／仍需客户决定的事项：
```

机器交换格式见 [SOP 定义](schemas/sop-definition.schema.json)、[步骤结果](schemas/step-result.schema.json)、[异常记录](schemas/exception.schema.json)。schema 只验证格式；权限、引用真实性、跨租户访问、金额守恒、状态推进由既有模块与服务端核验。`executionStatus` 是本次步骤报告状态，`verification` 是检查结论，都不是支付或 Workflow gate 状态。

完成报告至少有版本、产物、检查证据和限制；上线另需实际 URL、运行版本、健康结果及回滚入口。单元测试或模拟回执不能证明真实支付／退款成功。

格式示例：[步骤报告](examples/step-result.json)、[异常记录](examples/exception.json)、[单步骤定义摘录](examples/sop-definition.json)。示例值全部虚构，不能作为真实授权或证据。服务端还需验证步骤存在且唯一、Skill／模块注册、引用所有权、时间新鲜度及重试次数不超过上限；schema 格式验证不承担这些语义检查。

仓库维护时安装 `jsonschema==4.26.0` 后运行 `python scripts/validate-sop.py`，检查链接、清单引用、schema 和示例格式；云端 `Validate SOP` 执行相同检查。本轮不改运行系统。
